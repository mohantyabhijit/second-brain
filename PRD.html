Second Brain Research Agent

A source-grounded knowledge system that starts with saved X posts and YouTube videos, turns them into trustworthy summaries and timestamps, connects related ideas, and grows toward an autonomous research agent.

Problem Statement

The user saves high-signal material faster than they can consume it. Bookmarked X posts, YouTube Watch Later videos, Apple Notes, WhatsApp notes, and scribbled ideas become a fragmented backlog instead of retained knowledge.

Core constraint

The UI is only the presentation layer. The product value lives in ingestion, extraction, evidence preservation, synthesis, ranking, delivery, and feedback.

From the user's perspective

  • I bookmark posts but do not return to them consistently.
  • I save podcasts and videos but rarely finish the backlog.
  • My notes are split across Apple Notes, WhatsApp, scribbles, and memory.
  • I want retention and insight without spending Saturday morning manually triaging everything.

Solution

  • Connect to X bookmarks and a YouTube inbox playlist.
  • Extract original text, transcripts, metadata, quotes, and timestamps.
  • Summarize with source references and confidence boundaries.
  • Connect related concepts across saved sources.
  • Send a useful daily personal research newsletter at 5pm.

Functional Gist

A stable product pipeline that can be rendered by any UI, scheduled job, email template, CLI, or future agent surface.

1

Input

X bookmarks, YouTube inbox videos, and later notes, screenshots, documents, and rough thoughts.

2

Extract

Tweet text, article bodies, author data, video metadata, transcripts, source URLs, and timestamps.

3

Understand

Generate summaries, notable insights, best moments, action items, and confidence notes.

4

Connect

Cluster repeated themes, link related tweets and videos, and explain why sources belong together.

5

Deliver

Send a 5pm newsletter and use lightweight feedback to improve future selection and ranking.

Roadmap

The phases preserve the requested product sequence while making API risks and system boundaries explicit.

1

MVP: prove ingestion and summarization

Connect to X developer access, verify bookmark retrieval, fetch a small real sample, connect YouTube ingestion through the viable API path, extract transcripts where available, and summarize with source references.

  • Fetch 5 authenticated X bookmarks with tweet text, author, created time, metrics, and URL.
  • Summarize each bookmark with source quote or direct link.
  • Validate YouTube Watch Later access and document the official limitation if blocked.
  • Use a dedicated YouTube inbox playlist when Watch Later cannot be listed.
  • Extract at least one transcript and record transcript status for every video.
2

Improve the core product by understanding the user

Move from isolated item summaries to a personal knowledge layer that detects themes, connects similar ideas across sources, and learns from feedback.

  • Support more bookmarks and videos with normalized source records and synthesis cache keys.
  • Embed source chunks, summaries, entities, and themes for semantic retrieval.
  • Cluster related tweets, videos, and notes into source-grounded insight groups.
  • Explain why items were connected and preserve provenance for every claim.
  • Capture feedback such as useful, obvious, stale, irrelevant, more like this, and less like this.
3

Newsletter and self-learning loop

Generate and send a daily 5pm personal newsletter from saved material, ranked by relevance, novelty, source quality, age, and feedback signals.

  • Schedule digest generation in the user's configured timezone.
  • Mix related X and YouTube items when they cover the same concept.
  • Include original quotes, source links, video timestamps, and follow-up reading.
  • Expose lightweight feedback from the email and the app.
  • Polish the UI where it improves trust, source review, retention, and correction.
4

Multiple users

Add the account, permission, privacy, and operational model needed to let multiple people connect sources and receive personal research digests safely.

  • Add authentication and per-user OAuth source connections.
  • Encrypt and isolate tokens, source items, summaries, preferences, and digests by user.
  • Move ingestion and digest generation into observable background jobs.
  • Provide source disconnection, export, deletion, consent, and retention controls.
  • Ensure one user's failed source connection cannot affect another user's digest.

Implementation Decisions

The implementation follows the current repo direction: React presentation, Go API and pipeline, Supabase canonical storage, pgvector retrieval, and Neo4j as a derived graph index.

Source intake ledgerNormalizes X posts, YouTube videos, external IDs, source status, capture hashes, and ingestion audit records behind a stable interface.
Evidence artifact moduleStores raw and derived objects such as article text, transcript files, snapshots, and export artifacts with checksums and provenance.
Prompt synthesis moduleProduces summaries, insights, action items, quotes, timestamps, confidence, and hallucination guardrails from evidence-bearing inputs.
Knowledge run read modelReturns a UI-safe contract containing sources, summaries, insights, actions, processing events, validation, and blockers.
X connectorUses authenticated user access and bookmark scopes, then preserves tweet metadata and source URLs.
YouTube connectorUses a viable playlist path, handles Watch Later limitation, retrieves video metadata, and records transcript availability.
Embedding and retrievalStores chunk, summary, and entity embeddings in pgvector with model and dimensionality metadata.
Graph sync outboxDerives Neo4j nodes and relationships from canonical Supabase records and can be rebuilt when needed.
Digest generatorRanks sources by relevance, novelty, source quality, backlog age, and feedback before creating the 5pm newsletter.
Feedback learnerCaptures user signals and updates ranking, clustering, and digest selection without hiding the evidence trail.
Auth and tenant boundaryAdds accounts, per-user tokens, permissions, export, deletion, and row-level isolation in the multi-user phase.
Presentation layerRenders the Knowledge Inbox, source review, validation, and newsletter views without owning product logic.

Architecture commitments

  • Frontend clients call the Go API for product data; they do not connect directly to canonical storage.
  • Supabase Postgres is the relational system of record for source items, runs, validation, synthesis cache, and metadata.
  • Supabase Storage stores private raw and derived source artifacts.
  • pgvector supports semantic retrieval filtered by user, source type, run, timestamp, and permissions.
  • Neo4j stores derived entities, claims, concepts, summaries, and relationships for multi-hop reasoning.

API contract principles

  • Every generated output includes source attribution or an explicit reason evidence is unavailable.
  • Every run exposes validation and blocker data separately from generated summaries.
  • Transcript and translation status are first-class fields, not hidden implementation details.
  • Synthesis reuse is keyed by source identity, capture hash, prompt version, and model.
  • UI components receive view models and do not import connector or persistence logic.

Testing Decisions

Tests should assert external behavior at module boundaries. They should not lock the system to private implementation details that can change as the agent matures.

Connector tests

Use fixtures and mocked provider responses to verify X bookmark mapping, YouTube playlist limitation handling, metadata preservation, transcript status, and error surfacing.

Synthesis tests

Verify that summaries, insights, action items, quotes, confidence, and cache status are generated only from available evidence and reusable cache keys.

Artifact tests

Verify object metadata, checksums, paths, storage failure behavior, and provenance records without depending on a particular storage SDK.

Read model tests

Verify the Knowledge Run contract consumed by the UI, including blockers, validation, source health, summaries, insights, actions, and processing events.

Digest tests

Verify ranking, deduplication, idempotent scheduled generation, mixed-source sections, timestamp inclusion, source citations, and no duplicate sends on retry.

Multi-user tests

Verify tenant isolation, token scoping, export, deletion, disconnect behavior, background job scoping, and authorization on every user-owned read.

Risks, Scope, and Notes

Known constraints should shape the backend plan. The UI should surface state clearly but should not invent product capability.

X bookmark access

X bookmark lookup requires an approved developer app and authenticated user token with bookmark read scope. Phase 1 must validate access before downstream work assumes it.

YouTube Watch Later limitation

The official YouTube Data API blocks Watch Later item retrieval. The product should verify this in setup and use a dedicated Second Brain Inbox playlist or manual link import as the MVP fallback.

Transcript coverage

Not every video has usable captions. Transcript status, source language, translation status, and extraction errors must be visible in the data model.

Source-grounding risk

The product must avoid becoming a generic summarizer. Every generated claim should trace to a tweet, article body, transcript passage, timestamp, or explicit confidence warning.

Out of Scope

  • Multi-user support before the single-user ingestion and digest loop works.
  • Fully autonomous web discovery before saved-source understanding is reliable.
  • Generic recommendation feeds that are not grounded in the user's saved material.
  • Apple Notes, WhatsApp, screenshots, and scribbles before X and YouTube are proven.
  • UI polish that masks missing source access, missing transcripts, or weak evidence.
